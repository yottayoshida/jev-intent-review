# 凍結した実験仕様 v1（2026-09-20）

`#18` で事前に決めた終了条件を満たしたので、**次の比較実験で使う仕様として**ここを固定する。
**製品の既定動作に採用したわけではない**——`runReview`・レポート形式・閾値は今までどおり無変更で、
採用の判断は統合の段階に残る。

## 固定するもの

| 項目 | 実体 | 固定の意味 |
|---|---|---|
| 問いのテンプレート | `bench/check-questions-v4.ts` の `questionsV4` | 対象を名指し、`evidence.related` の役割を書き、「依存が返すものではなく対象がそれをどうするか」と言う |
| 選択肢 | `RESULT_CRITERIA_V3`（`returns_error` / `returns_success` / `cannot_determine`） | 排他。成功値の空・非空は問わない |
| 判定規則 | `verdictOfV3` | **結果の問いだけを読む。** 制御の問いは診断で、重みも多数決も付けない |
| 閾値 | `BAR_V3 = 0.6` | 結果を見てから動かさない |
| 証拠の形 | 対象本体 ＋ 計画が指定した**必要な呼び先**（`SELECTIONS["callee-only"]`） | 作り直さず、1 回作った packet の部分集合 |
| 保留 | `canAnswerLocally`（本体の切れ）＋ `referentsPresent`（必要な参照先が無い・一意でない） | **要求を送る前に**ローカルで決める |
| 出力 | 確認した節と未確認の節を分ける | `docs/real-requirement-check.md` の三段階と同じ |
| 採点 | 選択肢一致 と 一致かつ 0.6 以上 を**別々に**記録 | 0.51 の一致を 1.00 と同じに数えない |

## 固定しないもの（未採用のまま）

- **証拠の選び方の規則**（`no-tests` 等）。`buildEvidence` の既定の形（`as-is`）で v4 を
  測っていないので、採用の根拠が無い。しかも今の v4 は `evidence.related` を「対象が呼びうる
  コード」と説明しており、呼び元やテストが混ざる `as-is` に当てると**説明と入力が食い違う**。
  既定 packet との接続は、役割の区別も含めて統合時に確認する。
- `builder.ts` の呼び出し箇所収集がテスト領域を除外しない件・同じ範囲を 2 回送る件。
  コードと通常のテストだけで正当化できる独立した修正として残す。

## 回帰用に残すケース

`bench/fixtures/omamori-553-r2/`（omamori#553 R2 × `staging_info_from`、3 つのパッチ）と
`bench/logs/dependency-check-v1.json`。**新しい対象の成績と混ぜない。**

## v4 で確定したこと・していないこと

確定: **対象と依存の役割を明示すると、正しい答えが安定して採用基準を通る**
（対象変異版で v3 は 0.57/0.67/0.50・採用 1/3、v4 は 0.84/0.86/0.85・3/3）。

確定していない: 「v3 は依存の戻り値を対象の戻り値と取り違えていた」。同時測定の v3 は
3 回とも正しい側（`returns_success`）を**選んで**おり、低いのは確率だけ。`#17` で選択が
割れたことと整合する仮説にとどめる。**これを確定させる追加実験は、次へ進む条件にしない。**
